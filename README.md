# Study Buddy

Flashcard study app for three kids, with PDF upload, random-order quizzing, tests, and a parent analytics dashboard.

Stack: React/Vite on Vercel, Supabase (Postgres, Auth, Storage), two Vercel serverless functions in `/api`.

## One-time setup (about 20 minutes)

### 1. Supabase
1. Create a new Supabase project (separate from Sideline).
2. SQL Editor: paste and run `supabase/schema.sql`. (Already ran an earlier version? Run `supabase/migration-hybrid-scoring.sql` and `supabase/migration-scenarios.sql` instead.)
3. Authentication > Providers > Email: turn **off** "Confirm email" (kids have no real email).
4. Authentication > Users > Add user: email `paul@studyapp.internal`, a strong password, auto-confirm on.
5. SQL Editor, run:
   ```sql
   insert into profiles (id, username, display_name, role)
   select id, 'paul', 'Paul', 'admin' from auth.users where email = 'paul@studyapp.internal';
   ```
6. Project Settings > API: copy the project URL, the anon key, and the service_role key.

### 2. Vercel
1. Put this folder in a new GitHub repo (web upload works, same as Sideline), then import it in Vercel. Framework preset: Vite.
2. Environment variables (see `.env.example`):
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
   - `ANTHROPIC_API_KEY` (from console.anthropic.com)
3. Deploy, then optionally add a subdomain such as study.yourdomain.com.

### 3. Create the kids
Sign in as `paul`, open **Admin > Students**, and add each kid with a username, display name, grade, and password. They sign in with just the username and password.

## How it works

- **Login:** username + password. Under the hood the username maps to `username@studyapp.internal` in Supabase Auth. Only you (admin) can create accounts or reset passwords.
- **Privacy:** row level security means each kid sees only their own decks, PDFs, and history. You see everyone's analytics. PDFs live in a private storage bucket.
- **Adding material:** upload a PDF and pick one of two modes.
  - *Make flashcards from my notes:* Claude reads the PDF and writes up to 25 cards plus wrong answers for multiple choice.
  - *This PDF already has flashcards:* Claude copies the teacher's cards as written.
  - Either way the cards land in a review list first. Kids can edit or delete before approving.
  - Also supported: add cards by hand, or paste a list (CSV, or tab separated from Quizlet or a spreadsheet).
- **Application questions:** on a deck page, "Write application questions" has Claude write AP-style scenario questions from the deck's approved definition cards. The right answer and the wrong answers are all terms from the deck, the wrong ones chosen because they are easy to confuse, and each question has a short explanation shown after answering. They go to the review list first. Study setup can drill definitions only, application only, or everything.
- **Send a copy (admin only):** on any deck page, "Send a copy to a student" copies the approved cards (including application questions) to the students you tick. Each student gets their own copy with their own progress, and edits to one copy never affect another. Cards still waiting for review are not copied. Decks you create stay on your account until you send them.
- **Study modes:** Flip, Multiple choice, Type it, and Test (random cards, no hints, scored at the end).
- **Order:** "Smart" puts due and weak cards first, shuffled within groups. "Totally random" shuffles everything.
- **Spaced repetition:** 5-box Leitner system. Right answer moves a card up (reviewed after 1, 3, 7, 14 days), wrong sends it back to box 1, unsure keeps its box. "Mastered" means box 4 or 5.
- **Hybrid scoring (anti-cheat):** in Flip mode a kid rates themselves, but "Got it" and "Unsure" do not count yet. The card returns about 4 cards later as an auto-graded quick check (multiple choice, or typed if there are no choices) and only that result counts. "Missed it" counts immediately. Cards still waiting for their check when a session ends early get no credit.
- **Scoring:** right = 1, missed = 0 (flip self-ratings never score by themselves). Typed answers have an "I was right" override for false negatives; it is allowed in Type mode but never on a quick check, and the dashboard counts overrides so you can spot abuse.
- **Honesty check:** the analytics show what percent of flip "Got it" claims passed the quick check. A low number means they are over-rating themselves.
- **Study time:** counted only while the tab is visible and the student has clicked, tapped, or typed within the last 60 seconds, so a tab left open does not inflate minutes.

## Math facts

A separate module (Math facts in the top bar) for addition, subtraction, multiplication, and division. Problems are generated by the app, so answers are always correct and there is no AI cost.
- Pick any mix of operations and a number range (up to 5, 9, or 12), then either a practice round (10 to 50 questions) or a 60 second speed round.
- A fact counts as learned only when it is answered right and fast (3 seconds for addition and subtraction, 4 for multiplication and division), on several different days. "Fluent" means the fact reached box 4 of 5.
- New facts are introduced a few at a time, easiest first. Missed facts come back about 3 questions later and again first thing next session.
- In practice rounds a miss shows the answer and the student types it to continue.
- Each fact has its own history, so the dashboard shows exactly which facts are weak.
- Existing database? Also run `supabase/migration-math.sql`.

## Analytics (Admin tab)

- Definition accuracy vs application accuracy, so you can see if she knows the words but cannot use them. Trouble concepts roll up both kinds of question.
- Math facts: accuracy and speed by operation, weekly accuracy and speed trends, a color-coded fact map (like a times table) showing which facts are fluent, learning, or weak, and a list of the facts causing trouble.
- Weekly overview of all kids: minutes, sessions, average score, last active.
- Per kid: minutes per day (14 days), weekly minutes and weekly accuracy (8 weeks), test scores over time, last 14 days vs the prior 14 days accuracy change, mastery percentage, streak, per-deck breakdown, and the cards they miss most.

## Can't sign in?

- Kids sign in with their **username**. A parent account created with a real email signs in with that full email.
- In Supabase > Authentication > Users the admin's email must match what you type (or be `paul@studyapp.internal` if you sign in as `paul`) and show as confirmed.
- Supabase > Table Editor > `profiles` must have a row for that user (setup step 5).
- Supabase > Authentication > Logs shows the exact reason for each failed attempt.
- Message "missing its Supabase settings": add the Vercel variables, then **redeploy** (they are baked in at build time).
- The project URL is `https://<ref>.supabase.co` with nothing after it. The app now strips a pasted `/rest/v1/` automatically.

## Costs and limits

- PDF limit is 20 MB. Very long PDFs may time out at 60 seconds; split them by chapter.
- Each PDF costs a small amount of Anthropic API usage (typically cents).
- Change the model with `ANTHROPIC_MODEL` if you want.

## Local dev

```
cp .env.example .env.local   # fill in the values
npm install
npm run dev
```
The `/api` functions only run on Vercel (or with `vercel dev`).
